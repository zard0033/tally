## A. 必須在接上 Supabase 時一起做（會直接壞掉）

- [ ] **目標值 NaN 防護**。目標 1860 由 profile ＋ 最新 weight 前端算出。`active.md` 已標記 Google 登入可能建出第二個 UID 的風險——真發生時四張表全讀回空，畫面變成 `還能吃 NaN kcal`、進度條 `width:NaN%`。計算結果進 DOM 前要有守門，profile 缺漏時走降級畫面而非算式結果。
- [ ] **session 過期 ≠ 沒資料**。RLS 下未授權讀回的是 `[]` ＋ HTTP 200，不是錯誤（`active.md` 實測）。token 一過期，今日頁會安靜地長成「今天什麼都沒吃」。要在畫面上把「讀到空」與「沒有 session」分開。
- [ ] **載入態**。Supabase 一次 round trip，弱訊號 1–3 秒。主數字若先渲染 0 或目標值再跳成真值，「三秒瞄一眼」剛好會看到假數字。定義資料到位前顯示什麼，並保證主數字不出現中間假值。
- [ ] **寫入失敗回饋**。純前端直打 Supabase 無本地佇列，而記錄發生的地點（美食街、地下室）正好收訊最差。按完「記一筆」三秒關掉 app，不會發現沒存進去。不必做離線佇列（YAGNI），但失敗要當場看得見。
- [ ] **記錄流程的返回成本**。若「記一筆」是獨立頁面，每次返回＝整頁重載＋重打 Supabase，「三秒瞄一眼」變「三秒等載入」。決定同頁覆蓋層還是獨立頁；獨立頁的話今日頁要有本地快取。

## B. 沒設計過的狀態（畫面存在但沒人畫過）

- [ ] **空狀態**（每天早上第一次打開必遇）。四餐全待記錄、熱量條 0%、三條營養素條 0%，整個第一屏沒有一個 jade 像素，看起來像資料沒載到。要定義 0% 時進度條的最小可見態，以及待記錄行佔不滿時那約 250px 空白怎麼處理（不要靠加文案解釋，那已被否決）。
- [ ] **單一營養素破表、總熱量沒破**（幾乎每天）。比例 27/27/46 下脂肪最容易先破——現有常態屏自己就是證據：熱量才 48.5%，脂肪已 73%。此時主數字仍是 jade「還能吃」，但脂肪那欄是 6px 紅斜紋。`DESIGN.md` v1.4 已改寫訊號色規則允許這個組合，但**這一屏還沒實際畫過**。
- [ ] **破表 ＋ 仍有待記錄餐次**（每週數次）。真實的破表通常發生在一天還沒過完時（午餐吃爆、晚餐還沒吃），紅色量尺與虛線待記錄行同框。這是使用者最需要答案的時刻（「已經爆了，晚餐還要不要吃」），而此時主數字的「超出 229」對還沒吃晚餐的人資訊不足——文案可能要換。
- [ ] **中間餐次空著**（已發生過：`seed.sql` 顯示 2026-07-26 完全沒有早餐）。時間軸會是「早餐（空心）→ 午餐（實心）→ 晚餐（實心）」。虛實線規則 v1.4 已定（一律看下端節點），但這一屏沒畫過。
- [ ] **食品庫為空／搜尋無結果**。屬「記一筆」流程，但與 UID 分裂相關：新帳號時 foods 是空的，「新增食物」是唯一出路。
- [ ] **0 kcal 食物**（無糖飲料、代糖）。記錄後品項顯示 `0`、小計不變、量尺不動，跟「沒存到」無法區分。

## C. 第一版功能缺口

- [ ] **「刪除當天某筆」零入口**。`spec.md` 第一版白紙黑字的功能，但品項列不可點、無滑動、無長按。第一版又沒有編輯（第二版才有），刪除是唯一糾錯手段——沒入口＝一錯永久錯。
- [ ] **已記錄餐次無法追加**。早餐記完想補一杯咖啡，「早餐 293」整塊不可點，只能按 CTA 從頭再選一次餐別。同一條時間軸上兩種節點一可點一不可點，**而不可點的那種恰好是需要修改的那種**。
      → 建議：讓餐別標題列也成為入口，一次解掉這條和上一條。
- [ ] **記錄成功沒有確認訊號**。回到今日頁只有數字變了；記一個 70 kcal 的茶葉蛋，主數字 957→887 在三秒的一瞥裡不見得注意得到。建議新品項進場給一次極輕提示（只用 opacity/transform）。

## D. 邊界與規則（實作時會撞到）

- [ ] **`eaten == target` 的臨界**。「還能吃 0」還是「超出 0」？破表判定是 `>` 還是 `>=`？「超出 0 kcal」看起來像 bug。建議定為 `>` 才算破表。
- [ ] **長食物名截斷門檻**。實測 390px 下品名約 285px 才截斷，現有最長品名 `雞胸餐盒(糙米+萵苣)|波奇(Poki)` 佔 199px，安全。但使用者的命名法是 `品名|店家`（23 筆裡 8 筆帶 `|`），而**店家正是區分三個「雞胸餐盒」的唯一資訊**——截斷會先砍掉它。份量標記已加上，餘裕被吃掉了一些，實作後重測。
- [ ] **`prefers-contrast: more` / `forced-colors`** 完全沒處理。優先度低，但 `--ink-faint`、`--rule` 這些逼近門檻的用色沒有安全網。
