# lesson-rethink-from-user 從使用者怎麼想重做四個畫面的五條通則（2026-11-24，v2.162–v2.165）

1. **真機回報「不直覺」，先找畫面在哪把內部資料模型攤給使用者看**：通用食物（為共用數字而建）被直接當成清單列，使用者得先找到內部名字再補店家；改成「你點的名字就是一列」（別名各自一列）後使用者明講「不順著原本 UIUX 去想的效果不錯」。同一招再用在記一筆（搜尋／估一筆是系統的分法 → 一個框）、每日目標（公式推導是 app 怎麼算 → 只留目標體重＋速度）、熱量（每天一個額度 → 看這一週）。出方案時至少放一個不照現有畫面的。
2. **合併食物時，別名要拿掉被併掉的那個差異**：142 無糖拿鐵併入 143/144 時別名留著「（珍珠）」「（寒天晶球）」，145/147 留著「（去皮）」——加料／去皮已改按鈕，別名列一拆出來就變成「名字寫珍珠、熱量是基準」的假重複。合併後用全庫掃描查「別名品名含微調字、通用食物名不含」。
3. **規則的輸入與結果要分清楚**：每日目標選「速度當輸入、日期當結果」——速度一對一對應每天吃多少，用日期設定時落後會逼每天越吃越少；打平下限用 BMR（使用者裁決），目標本身低於 BMR 時下限取目標，否則整週誤報。
4. **委派寫 CSS 要在 brief 寫「新 class 用元件專屬前綴、先 grep app.css」**：v2.165 的 `.wk-title`／`.wk-bar` 撞到 WeeklyCompare，舊規則在後面贏，e2e 沒抓到、review 才抓到。
5. **CI 只在 CI 紅、重試過的三條（undo 焦點、切分頁錯誤、spring 回彈）都是「量得太早」類**：判環境差的條件＝本機 `--repeat-each` 全過＋這次改動沒碰那個元件；判完記進 `e2e-reference` 偶發紅清單、寫下「再紅就怎麼修」。另：背景指令 `… | tail` 的結束碼是 tail 的，通過與否看計數行；`gh run list --commit` 要完整 SHA，短的會靜默回空。
