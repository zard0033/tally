# Tally

[English](README.md) · **繁體中文**

[開啟 app →](https://zard0033.github.io/tally/)（需 Google 登入，裡面只有我自己的資料）

Tally 是一支營養追蹤 app，手機用，使用者只有我一個。我每天都在用，每次打開幾秒鐘：記下剛剛吃了什麼，看今天的熱量和蛋白質還剩多少，關掉。

## 它解決什麼問題

我在 Notion 記了好幾個月的每一餐。Notion 存得下那些列，卻算不出我要的東西：view 不能加總欄位，跨列運算得開 relation 欄，自動化三天兩頭壞。我每次打開那一頁只想看一個數字，今天還能吃多少，而那正好是 Notion 給不了的。

用 MyFitnessPal 可以省掉整個開發。代價是我的紀錄從此住在別人的 app 裡，而那正是我不肯換的：我要讓 AI 助理拿一週的攝取去對我的體重曲線，反推我一天真正燒掉多少。現成的追蹤 app 什麼都進不去。所以我自己寫了一支，把資料留在手上。

## 它做得到什麼

- 記一餐只要幾下：選餐別、從自己的食品庫選食物、填份量。庫裡沒有的食物加一次，之後就一直都在。
- 畫面主角是今天還剩多少額度——一條橫向熱量量尺配三條營養素條（蛋白、脂肪、碳水），掃一眼讀完。
- 目標依當前體重重算，會跟著我變動，不會停在舊數字上。
- 還能補記過去的日子、記體重、就地編輯某一筆、管理食品庫、在設定頁改身體參數。

## 那些決定是怎麼下的

這是我一個人的專案：我定規格、做設計系統、主導開發。下面幾個判斷決定了它現在的樣子。

### 第一版上線隔天我把它整個丟掉

原始 spec 寫著不用框架、不做 build、不載第三方程式碼。這句是我開案時寫下的，從來沒論證過——它是個預設值，只是看起來像個決定。回頭查它，翻出兩件事：自己手接 OAuth 跟資料層，成本比它省掉的那個依賴還高；而 `react-native-web`（未來要做成真手機 app 的那條路）不支援 CSS scroll-snap，那正是我左滑刪除手勢的根基。一條為了保持簡單而定的規矩，其實在默默保證核心互動總有一天要重寫。隔天我在 Vite + React + TypeScript 上重建。

### 算術完全不碰畫面

所有跟計算有關的東西都住在 `src/lib`，不准碰 DOM：BMR → TDEE → 目標的公式鏈、日期處理、捨入、資料庫存取。畫面在 `src/screens`。

這道邊界今天什麼也買不到。app 只跑在瀏覽器一個地方，而這條規矩讓我每加一個功能都多一點摩擦。我還是付，因為上架 App Store 是我想留著的選項，不是我許下的承諾。哪天 Tally 變成 React Native app，那一層原封不動搬過去，只有 UI 要重寫。現在付很便宜，以後才拆就得從那時累積的 UI 程式碼裡一點一點挖出來。

### 抽共用元件要有理由，長得像不算

一段 UI 能進 `src/components` 的門檻是：同一組欄位出現在兩個以上的畫面，而且兩邊本來就不該長得不一樣。目前只有一個共用元件，而它是在兩份副本已經分岔過兩次之後才抽出來的。看起來像就抽，等於許下一個你沒打算許的承諾：這兩個東西以後永遠會一起改。

### 74 條端對端測試，動 UI 就全部跑一次

74 條瀏覽器測試分在 10 個檔，另外 64 條單元測試守公式、日期與捨入。任何 UI 改動都要跑完整套瀏覽器測試，不是跑那個看起來相關的檔。全部跑完不到兩分鐘，而「我只跑了相關的測試」正是回歸缺陷溜出去最常見的方式。

每條新測試還要多做一次檢查：故意把它守的行為改回錯的，確認它會轉紅。沒紅過的測試，沒有人證明過它真的在測東西。

### 我決定不做的事

掃條碼（我吃的那些店不會在東西上印條碼）、食譜（我是一項一項記，不是照食材料理）、體態照片、運動、喝水、群眾食物庫。這些 MyFitnessPal 都有，每一項我都想過，然後都砍掉。

第一版設計稿有一個進度環，review 時被否決：環圈說的是「填滿就是達成」，熱量剛好相反。

## 設計

每一個顏色、字級、間距都是 [DESIGN.md](DESIGN.md) 裡定義的 token，程式碼裡不硬編任何一個。對比度是算出來寫在每個 token 旁邊的，不是用眼睛看的。

幾個花的時間比看起來多的決定：

- 不做暗色模式是刻意的，理由寫在 DESIGN.md，不是漏掉沒做。
- 沒有任何狀態只靠顏色傳達。某項營養素破表時，先是那條 bar 高度加倍，顏色是第二層；紅綠色覺者拿到的主訊號來自形狀。
- 一個半套的無障礙模式被判定比不做更糟：把餐別選擇器補成完整的 ARIA tablist，等於向讀屏使用者承諾方向鍵可以用，而實作裡沒有那個東西。它改用比較簡單的語意，那個承諾守得住。

DESIGN.md 帶一份版本紀錄，每一則都寫了改什麼、為什麼，包含那些被否決的想法。

## 技術棧

Vite · React 19 · TypeScript · Tailwind 4 · shadcn/ui（Base UI）· vaul · Motion · supabase-js

後端是 Supabase，Postgres 加 Google OAuth。託管在 GitHub Pages，由 GitHub Actions build 後部署。不從 CDN 載任何東西，所有依賴都打進 bundle 自架。

repo 是 public，所以瀏覽器手上只會有匿名 API key，每張表都在 row-level security 後面，沒登入的話任何查詢都回空的。service key、資料庫密碼、OAuth secret 不在 repo 裡，以後也不會進去。

## 本機跑起來

```bash
npm install
npm run dev        # http://localhost:5500
```

```bash
npx vitest run     # 64 條單元測試——公式、日期、捨入
npm run e2e        # 74 條瀏覽器測試，10 個檔（WebKit，393×745）
npm run build      # tsc -b + vite build
npm run lint
```

e2e 會先 build 再跑靜態 preview，所有網路請求都是 stub，不需要帳號、不碰真實資料。
